# P1-T11 decisions: MCP server

## Approach note (spec part1 2.5)

- Library: the official MCP Python SDK, `mcp` 2.3.0 (pin `mcp>=2.2,<3`). Released 2026-10-02; the 2.x line
  is current (2.0.0 on 2026-07-28) and the 1.x line (1.30.0) gets maintenance only. License verified from
  the repository LICENSE file: MIT (Copyright (c) 2024 Anthropic, PBC); PyPI metadata also says MIT.
- Entry point: `mcp.server.mcpserver.MCPServer` (v2 renamed `FastMCP` to `MCPServer`; the spec text says
  FastMCP), `MCPServer.streamable_http_app()` for HTTP, `MCPServer.run("stdio")` for stdio, and
  `mcp.Client(server)` for the in-memory test session.
- Known v2 breaking changes that affect us (from docs/migration.md): `FastMCP` rename; snake_case fields
  (`is_error`, `structured_content`); `httpx` replaced by `httpx2` inside the SDK (we keep using `httpx`
  for our own REST client, so we depend on it explicitly); transport parameters moved off the constructor;
  sync handlers run on worker threads (all our handlers are async); OpenTelemetry API is a new hard
  dependency. An unexpected exception inside an `MCPServer` tool becomes `isError` with `str(exc)` as the
  text, which can leak internals, so every tool catches everything itself and returns its own
  `CallToolResult`.
- Mitigations: tool bodies never let an exception escape; ToolFailure carries a stable code and a safe
  message; unknown exceptions are logged to stderr and reported as `internal_error`.
- Fallback: none needed at runtime; if 2.x regresses, the server only uses `MCPServer.tool/resource/prompt`,
  `streamable_http_app` and `Client`, which exist with the same shape in 1.x under `FastMCP`.

## Decisions

1. **Cursor format.** The MCP cursor is unpadded base64url JSON `{"v":1,"job","profile","page","r"}` where
   `r` is the renderer's own opaque cursor (frontmatter `truncation.next_cursor`, itself `{v, profile,
   unit}`). This satisfies 4.4.2 (job id, profile, page index, version) while all splitting stays in the
   renderer. Bare renderer cursors (the comment at the end of a page body) are refused with a message that
   points at `next_cursor`.
2. **Budget includes the frontmatter and footer.** The renderer budgets only body units; the server
   re-renders with a smaller body budget until the whole text block (frontmatter on page 1, body, footer
   with the next cursor) is at most `max_tokens` o200k tokens. If the renderer's smallest page is still
   too big (page 1 head: orientation line and contents list are not budgeted by the renderer) the result
   says `over_budget: true` instead of truncating content.
3. **`pages_total`** is exact on the last page and `ceil(tokens_total / max_tokens)` before it, flagged
   with `pages_total_estimated`. An exact count would render the whole document once per page.
4. **Allowed roots default to the working directory only** (task brief), not cwd plus home as 4.4.2 says.
   Home is a much larger blast radius for a model-driven tool; users widen it with `--allowed-dirs`.
   Paths must be absolute (4.4.2), may not contain `..`, are resolved (symlinks followed) before the root
   check, and `/etc`, `/proc`, `/sys`, `/dev`, `/boot`, `/root`, `/run`, `/var/run` are always refused.
5. **HTTP auth.** Token required by default (part1 8.4). Loopback without a configured token generates a
   random one and prints it to stderr; a non-loopback bind without an explicit token exits 2 with
   "refusing to bind non-loopback host ... without a bearer token" (4.4.6). `--no-auth` is loopback-only.
   `INTOMD_MCP_BIND` sets the host. Constant-time comparison; 401 carries `WWW-Authenticate: Bearer`.
6. **`convert_url` accepts only http(s).** The library treats any non-URL string as a path, so the tool
   refuses other schemes (`fetch_refused_scheme`) before calling it. Netguard raises one `UrlBlocked` class
   for every refusal, so the server maps its message to `fetch_refused_private_network` /
   `fetch_refused_scheme` (see core change request below).
7. **`allow_private_networks` is server-gated.** A tool call may set it only when the server was started with
   `--allow-private-networks`, so converted content cannot steer the model into intranet fetches.
8. **Local job store** is an in-memory LRU of 32 `Result` objects (IR retained so other profiles and pages
   render without re-converting). Nothing touches disk.
9. **Remote mode** creates jobs with `POST /v1/convert`, polls `GET /v1/jobs/{id}` with backoff up to
   `--wait-seconds` (default 120), pages with `GET /v1/jobs/{id}/result?format=md&max_tokens&cursor`, and
   reads sections and full warnings once from the unpaged `format=json` result. API error codes pass
   through verbatim. No local fallback.
10. **`search_result`** (P2-T11) is not registered.
11. **Registry listing.** `server.json` uses schema 2025-12-11; the `remotes` entry is a URL template
    `https://{host}/mcp` with a required secret `Authorization: Bearer {api_key}` header, because the public
    instance URL is not fixed yet. The schema is vendored at `packages/mcp/tests/data/server.schema.json`
    (MCP registry, MIT/Apache-2.0) so validation runs offline.

## Core change requests

- `intomd.core.netguard`: give `UrlBlocked` distinct codes per reason (`fetch_refused_scheme`,
  `fetch_refused_private_network`, `url_blocked`) instead of one class; the MCP server currently maps by
  message text.
- `intomd.render`: count the page-1 head (summary, orientation, contents) against `max_tokens`, or move it
  to its own page, so a budget is always honoured.
- Part 3 API: mount `intomd_mcp.http.build_http_app(server, token=None)` at `/mcp` behind the API-key
  middleware (4.4.3 item 2); not part of this task's ownership.
