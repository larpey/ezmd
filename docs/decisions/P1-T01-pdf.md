# P1-T01 (PDF part): decisions

## Approach note: PDF converters (spec part1 2.5)

- Libraries (versions verified 2026-10-08 on PyPI, license files read from the installed wheels):
  - pikepdf 10.16.0, MPL-2.0 (`licenses/LICENSE.txt`; wheels vendor qpdf Apache-2.0, libjpeg-turbo, zlib, openssl;
    Windows wheels also carry the GCC runtime under GPL-3.0 with the GCC Runtime Library Exception). Entry point:
    `pikepdf.open(path, password=...)`, object walk, `Pdf.save(encryption=False)`.
  - pypdfium2 5.14.0 (PDFium 156.0.8076.0), BSD-3-Clause OR Apache-2.0 (`licenses/LICENSES/*.txt`), bundled
    PDFium BSD-3-Clause with permissive third-party libs (freetype FTL, libjpeg-turbo IJG/BSD, lcms MIT, openjpeg
    BSD-2, libpng, zlib, ICU, abseil Apache-2.0). Entry points: `PdfDocument`, `PdfTextPage.get_charbox`,
    raw `FPDFText_GetFontSize/GetFontInfo/GetFontWeight/GetTextObject`, `FPDFPageObj_GetMarkedContentID`.
  - Docling 2.135.0 via `docling-slim[format-pdf,models-local,convert-core]` 2.135.0, MIT; docling-core 2.101.1
    MIT; docling-parse 7.22.2 MIT; layout model docling-layout-heron and TableFormer from
    `docling-project/docling-models` (Apache-2.0 / CDLA-Permissive-2.0 per spec 1b). Entry point:
    `DocumentConverter(format_options={InputFormat.PDF: PdfFormatOption(pipeline_options=PdfPipelineOptions(...))})`,
    `.convert(path, page_range=(a, b))`, `DoclingDocument.iterate_items(included_content_layers=...)`.
- Known issues and mitigations:
  - PDFium reports a line-end hyphen as U+0002 and soft hyphens as U+00AD: both map to `-` before dehyphenation.
  - `PdfPage.get_size()` is rotation-aware while char boxes are in unrotated user space: sizes come from the crop
    box and the converter applies `/Rotate` itself.
  - Docling's layout model labels section headers without hierarchy: levels are re-derived from the structure
    tree / outline / font sizes measured by the pdfium pass.
  - Docling downloads models from Hugging Face on first use: `HF_HUB_OFFLINE=1` unless `allow_network`;
    `INTOMD_DOCLING_ARTIFACTS` points at pre-fetched models.
  - The full `docling` meta-package pins typer<0.27 and websockets<17 (CLI/service client extras), so the extra
    uses `docling-slim` with only PDF extras. docling-core itself still requires typer<0.27, which downgrades
    typer 0.27.3 -> 0.26.8 for the whole universal lock (see "Core change requests" in the task report).
  - TableFormer imports cv2: `opencv-python-headless` is added to the `docs` extra (the full docling gets it via
    RapidOCR).
- Fallback: Docling (when installed) -> `documents.pdfium_text`. The text-layer engine emits `engine_fallback`
  itself when Docling is not installed (Docling is then `Unavailable` and skipped by the chain, so the registry's
  own fallback warning would not fire).
- Fixtures: `fixtures/pdf/*`, generated by `fixtures/pdf/_generate.py` with pikepdf from hand-built content
  streams (standard-14 fonts, no font files). Seven cases: born-digital-report, simple-table, two-column-page,
  image-only-page, encrypted-user-password, javascript-attachment, tagged-structure-tree. Goldens target
  `documents.pdfium_text` (the harness has no `requires` skip, so Docling goldens would fail without the extra);
  Docling is covered by `packages/converters/tests/pdf/test_pdf_docling.py` (skipped without extra + models).
- Threshold: 0.95 overall for both ids (`fixtures/pdf/thresholds.toml`); the harness scores one overall number,
  so the spec's per-dimension minimums (1g) are enforced by the golden review and unit assertions.

## D-P1-T01-pdf-1: pypdfium2 instead of pypdf for the default text layer

Context: spec 1b names pypdf for the fallback ("never produces tables or headings"); the roadmap allows a
permissive engine with char bboxes. Decision: pypdfium2 (BSD-3/Apache-2.0) for text, pikepdf for trailer,
passwords, outline, structure tree, links, and forms. pypdf is not a dependency. The converter id is
`documents.pdfium_text`; `pdf.engine=pypdf` is accepted as an alias. Rationale: per-character boxes, font sizes,
weights, and marked-content ids make headings, columns, running headers, tables, and structure-tree mapping
possible in the default install; pikepdf is already required by part1 8.2, so pypdf would be a third PDF parser.
Consequences: the default install gains ~4 MB (pdfium binary); the text-layer engine does produce headings and
best-effort tables, and its `engine_fallback` message says so.

## D-P1-T01-pdf-2: sanitization wins over embedded-file conversion

Part1 8.2 (strip `/EmbeddedFiles`, warn `attachment_skipped`) conflicts with part2 1c step 14 (convert each
embedded file as a child). The task brief and the security section win: attachments are removed and named in
warnings. Converting them as children (via `ctx.convert_child`) can be added later by extracting them before
stripping.

## D-P1-T01-pdf-4: `encrypted_no_password` instead of `encrypted_content`

Part1 8.2 says encrypted files with a non-empty user password are rejected with `encrypted_content`; part2 1c
step 3 and 13.6 use `encrypted_no_password` (error) with a stub paragraph. The part2 code is used because it is
more specific: it names the PDF case and its suggestion (supply `pdf.password`), while `encrypted_content` is the
generic notes/data code. The stub has no page provenance and no page marker, because no page was read.

## D-P1-T01-pdf-3: page cap uses ConvertOptions.max_pages

`ConvertOptions.max_pages` (default 500) is the shared cap; `pdf.max_pages` can only lower it. The spec's PDF
local default (2000) is the `Limits.max_pages` declared on the converters.

## New dependencies

- pikepdf `>=10.0,<11` (10.16.0), MPL-2.0, ~5 MB wheel (+ Pillow, lxml, packaging): sanitization, metadata,
  outline, structure tree, forms (spec part1 8.2).
- pypdfium2 `>=5.0,<6` (5.14.0), BSD-3-Clause / Apache-2.0, ~3-4 MB wheel: text layer with boxes.
- extra `docs`: docling-slim[format-pdf,models-local,convert-core] `>=2.135,<3` (2.135.0), MIT, ~1.2 GB with torch:
  layout engine. opencv-python-headless `>=4.10` (5.0.0.93), Apache-2.0 (bundled FFmpeg is LGPL, dynamically
  linked), ~40 MB: TableFormer dependency.
- Pillow 12.3.0 arrives transitively through pikepdf; its metadata says `MIT-CMU`, which is not in the allowlist
  (HPND is). See the task report.
