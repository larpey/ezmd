# P1-T18 decisions: `intomd shadow-run`

## Approach note (spec part1 2.5)

- No new dependency. The command reuses the registry (`ConverterRegistry.candidates`, `available`,
  `unavailable_for`), the one conversion path (`intomd.convert` with `Options.converter` forcing each engine),
  the golden scorer (`intomd.testing.score.score`), and `rich` tables (already a core dependency through the
  CLI). Module: `packages/core/src/intomd/cli/shadow.py`, registered as `intomd shadow-run`.
- Fallback: none needed; nothing here calls an external engine directly.

## Decisions

1. **Which engines run.** For each input: the registry's own order first (chain members plus more-confident
   specialists, exactly what `intomd convert` would try), then every other available converter whose
   `can_handle` is above zero, sorted by (confidence, priority, id). This is how chain alternatives and
   generic fallbacks (`text.plain` for HTML, `code.repo_pack` for archives) get compared too.
   `Unavailable` registrations that would claim the input (`unavailable_for`) are listed as "skipped" with
   their reason and the extra that enables them; they never run. A `can_handle` that raises counts as 0.
2. **Reference engine.** The first engine in registry order that succeeded, which is the converter an
   automatic conversion would have used (the registry also falls through on failure). With `--engines`,
   the reference is the registry's choice among the selected engines.
3. **Similarity.** Each engine's Markdown (rendered in `--profile`, default `full`) is scored with the golden
   scorer, reference as "expected": the table shows `text` (rapidfuzz ratio of paragraph text) and
   `structure` (block-type count agreement). The scorer is asymmetric, so `--json` `pairs` lists each
   unordered pair once with the earlier engine (registry order) as expected, plus heading, table and
   overall sub-scores. No metric is reimplemented.
4. **Counts.** `blocks` is top-level blocks of the document and its children (archive members,
   attachments); `headings`/`tables` come from `Document.counts(include_children=True)`; `warnings` is
   the rendered warning list (pipeline warnings included).
5. **Fixture-aware discovery.** A directory tree that contains `meta.toml` files is treated as a fixture
   corpus: only each fixture's `input.*` (not `input.url`, as in `Fixture.input_path`) is converted, so
   goldens, sidecars, `meta.toml`, `thresholds.toml` and `_generate.py` are not compared. Other directories
   are walked recursively, skipping dotfiles and `.intomd.json` sidecars. Globs are expanded recursively.
   Inputs are deduplicated by resolved path and sorted.
6. **Exit codes.** 0 whatever the engines did (failures are data in the table); 2 for usage errors (unknown
   profile, `--engines` token that names no registered converter, `--timeout <= 0`, a path or glob that
   matches nothing); 130 on Ctrl-C. `--engines` accepts full ids or the last id segment (`plain`).
7. **Timeout.** `--timeout` sets `Options.max_seconds` per engine run. It is the cooperative converter
   deadline (`ctx.check_deadline`), not a hard kill: an engine that never checks the deadline can overrun.
8. **Piped output width.** When stdout is not a terminal the table is drawn 120 columns wide so ids are not
   truncated in logs and CI; in a terminal rich uses the terminal width.

## Verification

`uv run intomd shadow-run fixtures` on this machine (default extras): 59 fixture inputs, 26 with two or more
engines, exit 0, about 4.5 s. Docling, LibreOffice, py7zr and pyarrow converters show as skipped with reasons.
