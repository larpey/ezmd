# P1-T15: integration workflow, security test tiers, Playwright suite

Spec: docs/spec/part4.md 4.14.3 (integration), 4.14.5 (security tests), 4.14.6 (browser tests), 4.15.1;
ROADMAP P1-T15 ("integration job green").

## Decisions

### D-P1-T15-1: one integration job in its own workflow, two stack phases
`.github/workflows/integration.yml` runs on push to `main`, nightly (04:23 UTC) and on demand, not on PRs
(4.14: "integration, load, and browser tiers on merge to main and nightly"). The stack comes up through
`tests/integration/stack.sh up`, which reuses `deploy/bootstrap.sh --plain-http --build` (env file, secrets,
migrations, owner key in keys.json, `compose up --wait`, `deploy/smoke.sh` with its non-root / read-only /
no-egress container checks), so the integration job exercises the same path an operator does.
- Phase 1 runs with the stack as shipped (`EZMD_ALLOW_PRIVATE_NETWORKS=false`): network-tier security
  tests, the REST suite with the owner key (unlimited, so it never touches the anonymous limits), then the
  anonymous rate-limit test on a fresh window (exactly the 21st creation in 60 s is refused).
- Phase 2 (`stack.sh private`) recreates the app services with private fetches allowed and the anonymous
  creation limit raised to 200, then runs the URL tests and Playwright. The browser has no API key, so the
  default 20/min would make the suite flaky with retries.
The spec's draft job used `https://localhost`; plain HTTP on :8080 is what the existing smoke job uses and
avoids trusting Caddy's internal CA in three tool chains. Alternative rejected: `uv run uvicorn` with the
inline queue (no RQ, no Caddy, no worker isolation, so not an integration test). It still works for local
runs (`PLAYWRIGHT_BASE_URL=http://127.0.0.1:8000`).

### D-P1-T15-2: in-network fixture server instead of a host server
`tests/integration/compose.fixtures.yml` adds `fixtures` (the api image running `python -m http.server`,
read-only, non-root, caps dropped, `fixtures/web` mounted read-only) on the `internal` network with the
dotted alias `web.fixtures.example`. The alias passes submit-time validation and is refused by
worker-fetch after DNS resolution (private address): that is the network-tier DNS-to-private SSRF case. In
phase 2 the same URL is fetched for the URL-input tests. No host networking or `host.docker.internal`.

### D-P1-T15-3: security tiers by marker, enforced
`tests/security/conftest.py` marks every test without `network` as `fast` and wraps fast tests in a guard
that refuses socket connects outside loopback (fails with "mark it `network`"). `network` tests skip unless
`EZMD_NETWORK_TESTS=1` and `EZMD_BASE_URL` are set (the existing pyproject marker text). The plain
`pytest packages apps tests` run in ci.yml therefore already runs the fast tier on every PR; no ci.yml
change was needed. `pytest tests/security -m fast` / `-m network` select a tier explicitly.
The SSRF table (4.14.5 item 1) lives in `tests/security/ssrf_table.py`: 54 literal URLs, 7 names resolved
by a fake resolver, 2 internal-port URLs (63 total). The API reports all of these as `url_blocked` (422);
the spec's `fetch_refused_private_network` / `fetch_refused_scheme` codes do not exist in this API
(D-0017 vocabulary); tests assert the codes the API actually has.

### D-P1-T15-4: Playwright layout and browsers
Specs stay in `apps/web/e2e/` (the existing `testDir`; spec 4.14.6 says `apps/web/tests/`, but `e2e/` was
established in P1-T13 and keeps Vitest and Playwright apart). Shared fixtures in `e2e/helpers.ts`: an auto
fixture that skips before a browser starts when `/healthz` is unreachable, and one that fails any test whose
page contacted an origin other than the instance (Turnstile excepted), covering "no third-party requests".
One worker (anonymous per-IP limits are shared). Projects: Desktop Chrome, and `mobile` = iPhone 13
descriptor rendered by Chromium (one browser download in CI). Known product defects are pinned with
`test.fail` so they flip to failures when fixed.

### D-P1-T15-5: netguard refuses internal service ports by denylist
Spec 4.14.5 item 1 wants "ports 6379 and 5432 on public hosts" refused; part1 8.3 names no port rule. An
allowlist (80/443 only) would break documents served on 8080, 8443, 3000 and similar, so
`netguard.BLOCKED_PORTS` lists non-HTTP internal services instead (Redis, Postgres, MySQL, MongoDB,
Memcached, Elasticsearch, Docker 2375/2376, AMQP/RabbitMQ, Kubernetes 6443/10250/10255, etcd 2379/2380,
Consul 8300/8500/8501, Kafka, ZooKeeper, Cassandra, CouchDB, epmd, MSSQL, Oracle, NFS, SMB/RPC, SSH, Telnet,
FTP, mail). `validate_url` checks the effective port on every redirect hop; `allow_private` lifts it, like
the address rules. Residual risk: an internal service on an unlisted port; extend the list when found.

## Findings

All eight were fixed on branch `task/P1-bugfix-e2e-findings` (one commit each, `Task: P1-T15`); their
`xfail`/`test.fail` markers are removed so the tests assert the fixed behaviour. Original reports:

1. deploy (HIGH): `deploy/env.example` has `EZMD_WEB_DIST=` (empty). Through `env_file` the empty value
   replaces the api image's `ENV EZMD_WEB_DIST=/app/apps/web/dist`; settings ignore the empty value and fall
   back to `default_web_dist()` (`.venv/apps/web/dist`, absent), so a bootstrapped stack answers 404 on `/`
   (no web UI). smoke.sh does not check `/`. Fix: set `EZMD_WEB_DIST: /app/apps/web/dist` in
   `x-app-env` in docker-compose.yml (like `EZMD_BLOB_FS_ROOT`) or drop the line from env.example; add a
   `/` check to smoke.sh. `stack.sh up` pins the path in the test env file until then.
2. web (MEDIUM): `InputPanel.addFiles` copies the input's live `FileList` inside the `setFiles` updater,
   after `e.target.value = ""` emptied it. When React cannot apply the update eagerly (e.g. a profile radio
   was just clicked), chosen files are silently dropped. Fix: `const picked = Array.from(list)` before
   `setFiles`. Pinned by `convert.spec.ts` "files chosen right after a profile change are kept" (test.fail).
3. web (MEDIUM): frontmatter `tokens` is an object (`{cl100k_base, o200k_base, claude_approx}`); `JobCard`
   reads it as a number, so the token badge and history token counts never render. Pinned by test.fail.
4. web (LOW, a11y): on a phone viewport the Raw tab's `<pre class="raw">` scrolls horizontally without being
   focusable (axe `scrollable-region-focusable`, serious). Fix: `tabIndex={0}` on the pre (or make the
   tabpanel the scroller). Pinned by test.fail in mobile.spec.ts.
5. web (LOW): after a pasted-text job finishes, the history title becomes "pasted" (frontmatter title from
   the SDK's `pasted.txt` filename) instead of "Pasted text (N words)".
6. api (LOW): `/admin` returns the SPA `index.html` (200) via the catch-all; 4.14.5 item 7 wants 404 from
   the public side. Strict xfail in test_net_stack.py.
7. core (MEDIUM): netguard does not refuse internal service ports (6379, 5432, ...) on public hosts
   (4.14.5 item 1). Strict xfails in test_ssrf_table.py. Request: a port denylist in `validate_url`.
8. detection (LOW): an uploaded inline-XBRL `.htm` (fixtures/edgar/synthetic-10k) is detected as XML and
   converted by `data.xml`; the EDGAR converter is only reached for URL inputs. Left out of the upload corpus.
