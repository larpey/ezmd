# P1-T10 decisions: API (Part 3) completion

Date: 2026-10-08. Task: P1-T10. Branch: task/P1-T10-api. Builds on D-0016 and D-0017.

## 1. REST options derive from `intomd.library.Options`

Decision: `intomd_api.options.ConvertOptionsIn` is generated with `pydantic.create_model` from the
client-settable subset of `Options` fields (`CLIENT_FIELDS`), copying each field's annotation and
constraints and making it optional (default `None`, so the library default applies). The other
`Options` fields are listed in `SERVER_FIELDS` with the reason they are server-controlled
(`max_seconds`, `max_bytes`, `experimental`, `converter`, `allow_private_networks`, `extra`, `render`).
The API adds two tightenings for hostile input (`asr_model` max 64 chars, `languages` max 10 items).
Validation also runs `Options.model_validate` on the result, and the conversion child builds
`Options(...).to_convert_options()` instead of constructing `ConvertOptions` itself.
Drift test: `apps/api/tests/test_api_options_drift.py` fails when an `Options` field is unclassified, a
classified field disappears, types or constraints differ, or a client field does not reach
`ConvertOptions`.
Alternatives: subclassing `Options` (inherits non-optional defaults and the server-controlled fields,
which clients must not set); a hand-written mirror (the drift the task asked to remove).

## 2. API keys: `keys.json` plus the database

Decision: `intomd_api.keys` serves both sources as one `KeyRecord`. `INTOMD_KEYS_FILE` (the task's name;
Part 4 4.9 calls it `INTOMD_API_KEYS_FILE`, recorded here as the deviation) points at a cobalt-shaped
JSON list. Entries carry `key_hash` = HMAC-SHA256(`INTOMD_KEY_PEPPER`, key), the same digest the
database stores, or a plaintext `key` that is hashed at load and never kept (cobalt compatibility;
the docs prefer `key_hash`). Per-key limits: requests per window and window length, requests per day,
concurrency, upload MB, duration, pages; plus `unlimited`, `tier`, `residential_allowed`, `expires`,
`ips` (CIDR allowlist), `user_agents` (glob allowlist), `allowed_sources` / `disabled_sources` (host
globs for URL inputs). Unknown fields are rejected. File keys get the stable id `kf_<first 16 hex of
the hash>` (jobs and concurrency are tracked by it).
Loading: at startup (a malformed file raises `KeysFileError` and the API does not start; messages never
contain key material) and on modification-time change, checked at most every 2 s on lookup. A file
that becomes malformed later keeps the previous keys and logs an error. No `SIGHUP` handler and no
`POST /admin/keys/reload`: Part 1 7.4 says "no admin HTTP endpoints", and mtime polling works on
every platform and under uvicorn's signal handling.
Not enforced yet: `allowed_families` (stored as before).

## 3. `intomd-admin` host CLI

Decision: a Typer app in `intomd_api/admin.py`, console script `intomd-admin` (the core `intomd` CLI
is being rewritten elsewhere; `intomd admin ...` can delegate to it later). Commands: `keys create
[--store db|file]` (prints the plaintext once; file keys are written atomically with mode 600),
`keys list [--json]` (never prints hashes), `keys revoke ID` (database: sets `revoked_at`; file:
removes the entry), `jobs list [--state|active] [--json]`, `jobs kill ID`, `reap [--now]`.
`jobs kill` cancels the RQ job (`Job.cancel()` when queued, `send_stop_job_command` when started) and
fails the job with `conversion_failed` and the message "An operator stopped this job." A dedicated
error code was not added because `docs/errors.md` (outside this task) must list every code.
Reaper: new `purge.reap_stale` fails fetching/converting/rendering jobs (not residential fetches) not
updated for the queue timeout plus 150 s with `timeout`, skipping jobs the queue reports as still
waiting (`JobQueue.waiting`), because handed-off jobs sit in `converting` while queued. The scheduler
runs it every 30 s. `purge.clean_temp` removes `intomd-job-*` / `intomd-upload-*` temp dirs older
than the job timeout plus 10 minutes (only from `intomd-admin reap`, since the scheduler runs in the
API container, not where workers write temp files).

## 4. `/metrics`: bearer token, not mounted by default

Decision: `GET /metrics` exists only when `INTOMD_METRICS_TOKEN` (at least 16 characters) is set, and
requires `Authorization: Bearer <token>` (constant-time compare) on every scrape. This follows Part 4
4.10.5 ("on the internal network with INTOMD_METRICS_TOKEN as a bearer"); Caddy's edge 404 is the
second control. A separate internal listener was rejected: it needs a second uvicorn server per API
process and compose changes outside this task. `INTOMD_METRICS_ENABLED` (Part 4 env list) is not
added; the token's presence is the switch.
No dependency: counters and the duration histogram are cumulative values in the state backend (Redis
hash `intomd:metrics`, memory in inline mode) so the API and every RQ worker process add to the same
series (Part 4's worker push to `/internal/metrics` is unnecessary with a shared Redis); gauges (jobs by
state and queue, queue depth, fetch nodes online) are computed from the job table and node heartbeats
at scrape time. Label values are escaped and bounded (converter ids, canonical warning codes, queue
and state names, rate-limit buckets). Series not built yet: `intomd_queue_wait_seconds`,
`intomd_fetch_blocked_total`, `intomd_blob_bytes`, `intomd_model_loaded`, `intomd_turnstile_verify_total`,
process metrics.

## 5. `GET /v1/warnings` and `JobOut.warnings`

Decision: `GET /v1/warnings` returns the registry from `intomd.warnings.codes` (code, severity,
family, description, suggestion, truncates, aliases), sorted by code, cacheable for an hour.
`JobOut.warnings` is the list of canonical codes the conversion emitted (aliases normalized, unknown
codes mapped to `other`, unique, first-seen order), stored in the new `jobs.warning_codes` column
(Alembic `0003_job_warning_codes`, JSON text, default `[]`).

## 6. OpenAPI annotations and lint

Decision: every operation has an explicit camelCase `operationId`, summary, description, tag (tags
carry descriptions), security (`ApiKey` optional header, `FetchNodeBearer`, or none), its 2xx
response with a schema, and its error responses grouped by status, all pointing at `ErrorResponse`
(the `apidoc.errors(...)` helper; descriptions list the codes per status). FastAPI's automatic 422
`HTTPValidationError` responses are removed because validation errors are `400 invalid_request` here.
`ConvertUrlRequest.options` references `ConvertOptionsIn`, which admits dotted override keys through
`patternProperties`. Response models were added for capabilities, health, readiness, and warnings.
`info` has license, contact, and servers.
Lint: Spectral 6.15.0 via `npx -y @stoplight/spectral-cli@6.15.0` with `apps/api/.spectral.yaml`
(`spectral:oas` plus operation-description, info-license, tag-description, oas3-unused-component as
errors) reports no problems at `--fail-severity hint`. `apps/api/tests/test_api_openapi_lint.py` runs
equivalent Python checks always and Spectral itself when `INTOMD_SPECTRAL=1`.
