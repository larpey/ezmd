## Core change request
- `ezmd.render.tables._html()` emits no empty cell where a cell is missing and no merge covers it, so any
  converter that omits empty cells in a merged table shifts columns (the xlsx fix works around it).

## Provenance check (`tools/check_fixture_provenance.py`)
- Rules: `[provenance]` present; `origin` one of self-generated, public-domain, cc0, cc-by; `license` in a
  per-origin allowlist (self-generated and cc0: CC0-1.0; public-domain: LicenseRef-US-Government-Work,
  LicenseRef-Public-Domain, CC-PDDC; cc-by: CC-BY-2.0/2.5/3.0/4.0, so no NC/ND/SA variants); non-empty
  `source` (an existing repo path or "hand-written ..." for self-generated, an https URL otherwise); every
  non-self-generated fixture has a CREDITS.md entry (`### fixtures/<family>/<name>` with Title, Author,
  License, URL, Retrieved) whose License and URL match meta.toml; stale CREDITS entries fail.
- Wiring: `tests/test_fixture_provenance.py` runs it on the real repository, so the ordinary pytest gate
  (`pytest packages tests fixtures`, CI's `pytest packages apps tests`) enforces it; the nightly workflow also
  runs the script directly.
- The four hand-written text fixtures had `source = ""`; they now say `hand-written for this repository (CC0)`.
- This is stricter than `ezmd.testing.fixtures.load_meta` (which only checks origin and a non-empty
  license). Core was not changed; folding the allowlist into `load_meta` is a possible follow-up.

## Nightly scorecard (`tools/scorecard.py`)
- Runs every fixture through `ezmd.testing.fixtures.run_fixture` (same path as the pytest plugin) and writes
  `scorecard.md` and `scorecard.json` (schema 1): totals, per-family and per-converter rows (fixture count,
  passed, failed, skipped, mean and min overall score, threshold, status) and per-fixture results with failure
  or skip reasons. Skipped fixtures (missing extras/modules/binaries) are reported, never counted as passes.
- `nightly.yml` goldens job: runs the provenance check, then (with `if: always()`) the scorecard into
  `$RUNNER_TEMP/scorecard`, appends the Markdown to the job summary and uploads both files as the
  `scorecard` artifact (actions/upload-artifact pinned to the same SHA as ci.yml). The scorecard exits 0 by
  default so it never masks the golden job's own result; `--strict` exits 1 on any failure.
- Default local output is `build/scorecard/` (git-ignored).

  starts in the top 30%; `attrs.pdf_table_row_pages` records row ranges per page.
- Provenance tool: self-generated `source` must be a relative path to an existing file in the repo or exactly
  `hand-written for this repository (CC0)`.
