# P1-T03 code converter: decisions

## Approach note (docs/spec/part1.md 2.5)

- Scope delivered: `code.source_file` and `code.repo_pack` (zip and tar.gz repository archives, GitHub
  repository URLs through `FetchRequired` to the codeload tarball), with native secret scanning. Remaining
  section 8 converters (PR, issue, diff, OpenAPI, Postman, SQL, config, log, stack trace) are separate tasks.
- Packing: implemented natively in Python, modeled on Repomix (MIT) and gitingest (MIT) behavior (tree,
  per-file fences, token counts, ignore rules). No code copied.
- `.gitignore`: pathspec 1.1.1 (MPL-2.0; license verified from `pathspec-1.1.1.dist-info/licenses/LICENSE`,
  "Mozilla Public License Version 2.0"). Entry point: `pathspec.GitIgnoreSpec.from_lines(...).check_file(rel)`,
  whose `include` is True/False/None, which lets nested ignore files override parents (deepest decision wins)
  and keeps `!negation` semantics. Known issues: gitignore's rule that a file under an excluded directory cannot
  be re-included is approximated per file. Fallback: none needed (pure Python, no native code).
- Tokens: tiktoken `cl100k_base` through `ezmd.render.tokens.TiktokenCounter` (already a core dependency;
  falls back to estimates offline).
- Secrets: native `re` rules modeled on Secretlint and detect-secrets plugins instead of a `detect-secrets`
  dependency. Reasons: detect-secrets runs its own file walking and plugin loading, its high-entropy plugin is
  noisy on lockfiles and hashes, and the rules we need fit in about 120 lines that run on text already in memory.
  Mitigation for coverage gaps: the rules table is one tuple (`ezmd_converters.code.secrets.RULES`) that later
  tasks can extend; `detect-secrets` (Apache-2.0) stays the documented upgrade if parity becomes a requirement.
- Signatures-only: stdlib `ast` for Python; the spec's regex heuristic for other languages. Tree-sitter with
  `tree-sitter-language-pack` (8b) is deferred to Phase 2 as the spec allows (8i): grammar wheels were not
  evaluated on all three CI platforms within this task.
- Archives: a minimal reader in the family (no archives package exists in main yet) enforcing part1 8.2:
  10,000 entries, `EZMD_ARCHIVE_MAX_BYTES` (500 MB) total, 100:1 ratio per zip entry and per gzip stream,
  no links, devices, absolute, drive-letter, or `..` paths, encrypted zip entries skipped, nothing extracted
  to disk, nested archives never opened. When an archives family lands, its reader can replace this one.
- GitHub: `github.com/<o>/<r>[/tree/<ref>[/<path>]]` maps to `https://codeload.github.com/<o>/<r>/tar.gz/<ref>`
  (`HEAD` when no ref). The converter never touches the network; the pipeline validates and fetches. The
  fetched tarball is recognized by its codeload URL (confidence 1.0); the pax global header `comment` carries
  the commit sha.
- Fixtures (all self-generated by `fixtures/code/_generate.py`, CC0, deterministic): `source-python`,
  `source-python-signatures` (`extra.signatures_only`), `source-planted-secret`, `source-go`,
  `source-typescript`, `repo-small` (nested `.gitignore` with negation, lockfile, binary, minified bundle, `.env`
  and `.pem`, `node_modules` and `build`, UTF-16 file, `_pb2.py`, planted secret, symlink and `../` entries),
  `repo-budget` (`extra.token_budget=1100`, all five budget actions; a compressed and truncated `scale.py` and a truncated `inventory.py` survive), `repo-github-tarball` (codeload URL,
  pax commit). Planted secrets are generic-assignment, PEM, and URL-password values derived from hashes;
  provider-format tokens (`AKIA`, `ghp_`, `xoxb-`, `sk_live_`) are built only at test runtime.
- Thresholds: `code.source_file` 0.99 and `code.repo_pack` 0.99 (spec 8g: code verbatim, 0.999 text similarity
  on included code; the harness score also weighs headings and counts).

## Decisions

- Single files get `Provenance.path` = file name (spec 8d makes `path` mandatory for the code family, which
  overrides the IR docstring's "None for single-file inputs").
- `.env*` files are excluded from packs outright (8b step 4) rather than packed with values redacted (the
  ConfigFileConverter behavior in 8c step 24, which is a separate converter).
- Gitignored files are hidden from the tree; default-excluded directories and rule-excluded files are shown.
- Secret redaction always runs; `redact=false` (8b step 4, CLI/self-host only) is not implemented.
- Budgeting counts the directory tree as overhead and estimates truncation proportionally per line
  (binary search for N), then recounts exactly.

- Redaction keeps the line structure: the marker is followed by as many line breaks as the secret contained.
  `metadata.extra.lines`, CodeBlock `line_end`, and `secret_redacted` locations therefore count source lines
  (Skeptic review of `source-planted-secret`).
- Deviation from 8b step 4 (sidecar `redactions` list of file, line, rule): the renderer's sidecar has no
  family-specific section and `Metadata.extra` holds scalars only, so the list currently lives in the
  `secret_redacted` warning detail (`rule.<name>` counts plus a `locations` string of `file:line`, capped at
  200), which the sidecar already serializes. Core change needed: a sidecar hook, for example a
  `Document.sidecar_extra: dict[str, list[dict[str, str | int]]]` (or `ConversionResult` field) that
  `ezmd.render.sidecar` emits verbatim under its key, so the converter can publish
  `redactions: [{file, line, rule}, ...]` without the 200-entry cap or string encoding.

## Dependencies

- pathspec >=0.12.1 (locked 1.1.1), MPL-2.0, about 420 KB installed, pure Python; gitignore matching for repo
  packs (spec 8b step 1). Already in the dev environment through mkdocs and mypy; now a runtime dependency.
