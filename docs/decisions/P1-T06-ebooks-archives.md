# P1-T06 (with the EPUB part of P1-T01): ebooks, notebooks, and archives

Decisions in DECISIONS.md style, to be folded into the log at merge (D-0020).

## Approach note: EPUB (`documents.epub`)

- Library: stdlib `zipfile` + `lxml` 6.1.3 (BSD-3-Clause; verified against
  https://github.com/lxml/lxml/blob/master/LICENSE.txt). Entry points: `lxml.etree.XMLParser`,
  `lxml.etree.fromstring`, `lxml.html.HTMLParser`, `lxml.html.document_fromstring`.
- Approach: container.xml -> OPF (Dublin Core metadata, manifest, spine) -> nav.xhtml (`toc`, `page-list`) or
  NCX (`navMap`, `pageList`) -> pre-scan of every spine document for footnote bodies and noteref markers ->
  per-chapter XHTML walk. The shared section 5 HTML-to-IR module does not exist yet (web family, P1-T02, built
  in parallel), so `ebooks/xhtml.py` is a small local walker; it should be replaced by the shared module once
  that lands, keeping the EPUB hooks (footnote ids, page ids, image resolver).
- Known issues researched: XXE and billion-laughs in XHTML (mitigated: `resolve_entities=False`,
  `no_network=True`, `load_dtd=False`, `huge_tree=False`, tested); HTML entities (`&nbsp;`) are fatal to an
  XML parse without the DTD and `recover=True` silently drops them and merges words (mitigated: any parser
  error triggers a re-parse with the HTML parser); zip bombs in EPUB containers (mitigated: the archive guard).
- Fallback: `archives.archive` in the `application/epub+zip` chain (lists the zip when the EPUB converter
  rejects it). Docling's EPUB backend is not wired (no `docs` extra in this task).
- Deviation: the "Non-linear content" heading is level 1, not the spec's level 2, because TOC chapter
  headings come out at level 1 (TOC depth); at level 2 it would nest under the last chapter.
- Cover (Skeptic review): the cover is recorded as `metadata.extra.cover_image`, not an Image block, because
  the renderers number every Image and the cover is not a figure of the text. If the renderer later learns
  to skip numbering for `attrs.role = "cover"`, it can come back as a block in `full`.
- Non-linear items that contain only footnote bodies add their footnotes without headings (Skeptic review:
  hollow "Non-linear content"/"Notes" headings). `metadata.pages` is the count of page-list labels; editors
  (`edt`) and other contributor roles go to `metadata.extra.editors` / `contributors`.
- DRM rule: `encryption.xml` entries whose algorithm is not font obfuscation (IDPF or Adobe) mark those files
  encrypted; encrypted spine documents are skipped with `drm_protected`, and an entirely locked book gets a
  stub paragraph. `rights.xml` alone (no encrypted resources) is not treated as DRM.
- Fixtures: `ebooks/epub3-novel`, `ebooks/epub2-ncx` (self-generated by `fixtures/ebooks/_generate.py`).
  Threshold 0.95 overall (spec 4g asks text 0.98 / headings 0.95; both fixtures score 1.0).

## Approach note: Jupyter (`documents.ipynb`)

- Library: stdlib `json`; Markdown cells via `ezmd_converters.text.markdown.parse_markdown` (imported, not
  copied); HTML outputs via the local XHTML walker in HTML mode.
- `nbformat` is not used: the spec allows it "for validation only", and it pulls jsonschema, fastjsonschema,
  jupyter_core, and traitlets. The converter checks the structure itself (nbformat >= 4 with a `cells` list)
  and warns `notebook_invalid` otherwise, reading nbformat 3 worksheets best-effort.
- Math: `parse_markdown` has no dollar-math plugin and is not ours to change, so `ebooks/mathspans.py`
  splits `$...$` into `InlineSpan.math` and `$$...$$` paragraphs into Equations after parsing. Raw cells
  are fenced with a language name (`text/x-rst` becomes `rst`). DataFrame tables with an empty index header
  cell carry `Table.attrs.header_synthesized = "true"`.
- Code is verbatim. The Skeptic saw reformatted quotes and blank lines in the first golden: `ruff format .`
  formats ````python` fences inside `fixtures/**/expected.full.md`. The fixture now uses ruff-style code so
  the golden is verbatim and the format gate passes; a unit test asserts verbatim non-ruff code.
- Output fence language is `output` for every output kind (per the task brief); `attrs.role` distinguishes
  `output` from `error`. The spec's `Code(language="text", role=...)` is otherwise followed.
- `output_truncated` is a retired alias of `truncated` (D-0017), so the cap emits `truncated` with
  `detail.reason = "notebook_output"`.
- Fixture: `ebooks/ipynb-analysis`; threshold 0.95 (scores 1.0). The golden carries `misnamed_file` because
  core detection reports notebooks as `application/json` (see core requests).

## Approach note: archives (`archives.archive`)

- Library: stdlib `zipfile`, `tarfile` (stream mode `r|`), `gzip`, `bz2`, `lzma`; `py7zr` 1.1.3 for 7z.
- Limits per part1 8.2 (binding) in `archives/guard.py`: total 500 MB (`EZMD_ARCHIVE_MAX_BYTES`, or
  `specialized.archive_max_total`), 10,000 entries, depth 3, 100:1 per-entry ratio, one shared `Budget` for
  nested archives, and a 100 MB per-member in-memory cap (InputRef's default `max_bytes`). Part 2 section 12's
  CLI defaults (2 GB total, 500 MB per entry) are superseded by part1 8.2's binding 500 MB total.
- Ratio floor: the 100:1 cap applies once a member has produced more than 1 MiB, so small repetitive text
  files are not false positives. For tar streams the ratio is measured over the whole compressed stream.
- Declared-size precheck plus streaming counts: zips that declare too much (or any entry over 100:1) are
  listed with nothing extracted; every read is counted chunk by chunk because headers lie. A zip whose
  end-of-central-directory record announces more than 10x the entry cap is refused before `ZipFile` parses
  the directory (memory bound).
- Warnings: traversal/absolute paths -> `archive_path_rejected`; symlinks, hard links, devices, FIFOs, and
  oversized members -> `archive_entry_skipped`; depth and entry caps -> `archive_truncated` (truncates).
  Warnings are grouped (one per code, with a count and examples) instead of one per entry.
- Nested archives are opened in-process (not through `convert_child`) so they share the parent's Budget and
  depth counter; other members go through `options.ctx.convert_child`. Zip-based documents are never opened
  as nested archives (extension list plus first-member check for `mimetype` / `[Content_Types].xml`).
- `application/zip` has no pinned chain so EPUB/Office converters can outrank the archive converter on
  zip-detected documents (`can_handle` returns 0.2 for those).
- 7z: py7zr is LGPL-2.1-or-later (verified against https://github.com/miurahr/py7zr/blob/master/LICENSE, an
  LGPL 2.1 text; its compression deps pyppmd, pybcj, inflate64, multivolumefile are LGPL-2.1-or-later too).
  Importing an unmodified, separately installed Python package is dynamic use, which the allowlist permits,
  so it does not belong in `nonfree`. Part 2 section 12 still keeps it out of the default install
  ("`ezmd[7z]` extra; default refuses 7z with `extra_required`"), so it is the optional `7z` extra of
  ezmd-converters; without it, 7z inputs get a stub with `extra_required` and capabilities lists
  `archives.sevenzip` as unavailable. Extraction goes through a py7zr `WriterFactory` that charges the
  shared Budget, so no 7z member touches disk.
- Fixtures: `archives/zip-mixed` (md, txt, directory, nested zip), `archives/tar-gz` (pax tar.gz with a
  symlink), `archives/zip-slip`; threshold 0.99 ("listing exact"); all score 1.0. Bomb fixtures are built in
  memory by `packages/converters/tests/archives/test_archive_bombs.py` (1 GB of zeros, 42.zip-style nesting,
  lying headers, tar.gz stream bomb, single-file gzip ratio bomb, 10,001 entries, entry flood, encrypted
  flags, traversal, absolute paths, symlinks in tar and zip, 7z when py7zr is present).

## New dependencies

- `lxml>=6.0` (locked 6.1.3), BSD-3-Clause, ~4 MB wheel, default dependency: safe XML/XHTML parsing for EPUB
  (container, OPF, NCX, nav, chapters) and notebook HTML outputs.
- `py7zr>=1.1,<2` (locked 1.1.3), LGPL-2.1-or-later, ~70 KB plus ~2 MB of compression wheels (pyppmd, pybcj,
  inflate64, pycryptodomex, brotli, backports.zstd), optional extra `7z` only: 7z archives.
